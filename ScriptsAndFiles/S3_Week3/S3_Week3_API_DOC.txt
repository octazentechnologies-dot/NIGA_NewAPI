APPOINTMENTS  (HOST = New-API)
================================================================================

--------------------------------------------------------------------------------
URL        : POST /api/PatientAppointment/SaveDailySchedule
USE        : Doctor sets one day. Unique per doctor+date and cannot be changed once set.
             Break must sit inside working hours. Reception is read-only (403).
HOST       : New-API
TOKEN      : doctor JWT
SAMPLE PAYLOAD:
{
  "doctorId": 1010,
  "scheduleDate": "2026-12-20",
  "slotIntervalMinutes": 15,
  "workStartTime": "09:00:00",
  "workEndTime": "12:00:00",
  "breakStartTime": "10:30:00",
  "breakEndTime": "10:45:00"
}
INPUTS     : doctorId, scheduleDate, slotIntervalMinutes, workStartTime, workEndTime,
             breakStartTime, breakEndTime optional
OUTPUT     : 200 schedule, or 400 (past date, bad interval, break outside hours, already set)

--------------------------------------------------------------------------------
URL        : GET /api/PatientAppointment/GetDailySchedule
USE        : Read one day. Reception uses this for /reception/schedule.
HOST       : New-API
TOKEN      : doctor or that doctor's reception
SAMPLE     : GET /api/PatientAppointment/GetDailySchedule?doctorId=1010&scheduleDate=2026-12-20
INPUTS     : doctorId, scheduleDate
OUTPUT     : workStartTime, workEndTime, slotIntervalMinutes, breakStartTime, breakEndTime
             404 when that day has no row. 403 for another clinic.

--------------------------------------------------------------------------------
URL        : GET /api/PatientAppointment/GetAppointmentSlots
USE        : The only slot calculator. Public Slots calls this same method.
             A cancelled appointment does not occupy a slot.
HOST       : New-API
TOKEN      : doctor or that doctor's reception
SAMPLE     : GET /api/PatientAppointment/GetAppointmentSlots?doctorId=1010&appointmentDate=2026-12-20&currentPatientAppId=27171
INPUTS     : doctorId, appointmentDate, currentPatientAppId optional (excluded so a move onto the same time is allowed)
OUTPUT     : { doctorId, appointmentDate, intervalMinutes, hasSchedule, slots: [ { time, label, status, patientAppId, patientName } ] }
             time is HH:mm:ss. status is available or booked.

--------------------------------------------------------------------------------
URL        : POST /api/PatientApp
USE        : Staff create. Existing route. Now stores VisitType, ConsultMode, IsTele,
             PaymentStatus=UNPAID, PayAtClinicAllowed=true, BookingChannel=Staff.
             Client PaymentStatus is ignored. A day with no schedule, or an invalid time, is 400.
             A taken slot is 409. Assisted booking uses the same create and sets BookingChannel=Assisted.
HOST       : New-API
TOKEN      : doctor or that doctor's reception
SAMPLE PAYLOAD:
{
  "patientAppId": 0,
  "patientId": 3065,
  "doctorId": 1010,
  "userId": 10032,
  "appointmentDate": "2026-12-20",
  "appointmentTime": "09:00:00",
  "status": "WAITING",
  "consultMode": "Tele",
  "visitType": "Tele"
}
INPUTS     : patientId, doctorId, userId, appointmentDate, appointmentTime, status, consultMode, visitType
OUTPUT     : 200 "Patient Appointment Saved Successfully", 400 when the slot is invalid, 409 when it is already taken

--------------------------------------------------------------------------------
URL        : GET /api/PatientAppointment/GetAppointmentsByDate
USE        : Existing list. Each row includes paymentStatus, visitType, consultMode, isTele, bookingChannel.
HOST       : New-API
TOKEN      : the userId on the query must be the caller, or admin
SAMPLE     : GET /api/PatientAppointment/GetAppointmentsByDate?userId=10032&appointmentDate=2026-12-20
OUTPUT     : array of appointment rows including paymentStatus

--------------------------------------------------------------------------------
URL        : POST /api/PatientAppointment/RescheduleAppointment
USE        : The recorded move. Validates schedule, interval, break, past time, and double-book.
             409 returns alternative open slots. Does not send SMS or WhatsApp.
             Moving onto the appointment's own current time is 200.
HOST       : New-API
TOKEN      : doctor, that doctor's reception, or the mapped patient
SAMPLE PAYLOAD:
{
  "patientAppId": 27171,
  "appointmentDate": "2026-12-20",
  "appointmentTime": "11:15:00",
  "reason": "clinic move"
}
INPUTS     : patientAppId, appointmentDate, appointmentTime, reason optional
OUTPUT     : 200 { statusCode, message, appointment, alternatives }
             409 when the slot is taken, with alternatives
             403 for another clinic or an unmapped patient

--------------------------------------------------------------------------------
URL        : POST /api/PatientAppointment/UpdateAppointmentTime
USE        : Existing quiet time change. Does not write AppointmentChangeLog and does not notify.
             Use RescheduleAppointment when the change must be recorded.
HOST       : New-API
TOKEN      : doctor or that doctor's reception. Patient is 403.
INPUTS     : patientAppId, appointmentDate, appointmentTime
OUTPUT     : updated appointment, or 400

--------------------------------------------------------------------------------
URL        : POST /api/PatientAppointment/CancelAppointment
USE        : Sets status CANCELLED, stores reason, frees the slot.
             APT-06.04 stub: the oldest JOINED waitlist row for that doctor and date
             becomes OFFERED. No SMS, no auto-booking. Full waitlist capture is Phase 9.
             If nobody is waiting, waitlistOffer.offered is false.
HOST       : New-API
TOKEN      : doctor, that doctor's reception, or the mapped patient
SAMPLE PAYLOAD:
{ "patientAppId": 27171, "reasonCode": "PatientRequest", "reasonText": "" }
INPUTS     : patientAppId, reasonCode, reasonText (required when reasonCode is Other)
OUTPUT     : 200 appointment with status CANCELLED
             400 when Other has no text, or the reason code is unknown

--------------------------------------------------------------------------------
URL        : POST /api/PatientApp/UpdateAppointmentStatus
USE        : Existing status route the dashboard already calls.
             CANCELLED is refused. Use CancelAppointment.
HOST       : New-API
TOKEN      : doctor or that doctor's reception
SAMPLE PAYLOAD:
{ "patientAppId": 27171, "status": "COMPLETED" }
OUTPUT     : 200 for WAITING, WALK-IN, E-CONSULT, REMAINING, COMPLETED
             400 "Use CancelAppointment. A cancel reason is required." when status is CANCELLED

--------------------------------------------------------------------------------
URL        : GET /api/PatientAppointment/ChangeLog/{patientAppId}
USE        : Reschedule and cancel history for one visit.
HOST       : New-API
TOKEN      : doctor, that doctor's reception, or the mapped patient
SAMPLE     : GET /api/PatientAppointment/ChangeLog/27171
OUTPUT     : { success, data: [ { appointmentChangeLogId, patientAppId, action, oldValue, newValue, byUserId, byRole, reason, at } ] }

--------------------------------------------------------------------------------
URL        : PATCH /api/PatientAppointment/{patientAppId}/VisitType
USE        : Correct visit type / consult mode on one row. Does not rewrite other rows.
HOST       : New-API
TOKEN      : doctor or that doctor's reception. Patient is 403.
SAMPLE PAYLOAD:
{ "visitType": "InClinic", "consultMode": "InClinic" }
OUTPUT     : 200 updated appointment

--------------------------------------------------------------------------------
URL        : GET /api/PatientAppointment/Queue
USE        : Today's WAITING, WALK-IN, and E-CONSULT for the caller's doctor. Not cancelled.
             Order is appointment time, then id. Paid does not jump the queue.
HOST       : New-API
TOKEN      : doctor or that doctor's reception
SAMPLE     : GET /api/PatientAppointment/Queue
OUTPUT     : { success, data: [ appointment rows with paymentStatus ] }

--------------------------------------------------------------------------------
URL        : POST /api/PatientAppointment/CallNext
USE        : Next today WAITING visit with CalledAt null. Sets CalledAt.
             WAITING becomes WALK-IN, or E-CONSULT when IsTele is true.
             404 when none remain today.
HOST       : New-API
TOKEN      : doctor or that doctor's reception
SAMPLE     : POST /api/PatientAppointment/CallNext   body empty
OUTPUT     : 200 the called appointment (status WALK-IN or E-CONSULT, calledAt set), or 404

USE        : Same slot engine as GetAppointmentSlots. No schedule is 400. A time that is not a slot,

             ConsultMode is normalized. PaymentStatus stays PENDING. PayAtClinicAllowed is true.
             consultFee is the profile in-clinic or tele fee. Razorpay is not called.
             Requires a verified PatientAuth OTP (bookingSessionId).
HOST       : New-API
TOKEN      : no
OUTPUT     : 200 { success, data: { patientAppId, bookingToken, paymentStatus, holdExpiresAt, consentPolicyVersion, consultMode, consultFee } }
             400 when the time is not bookable. 409 when the slot is taken.

--------------------------------------------------------------------------------
URL        : GET /api/Public/Bookings/{bookingToken}
USE        : Payment status and the same consultFee for the patient app.
HOST       : New-API
TOKEN      : no
OUTPUT     : { success, data: { patientAppId, doctorId, status, visitType, consultMode, paymentStatus, isTele, bookingToken, consultFee, ... } }

--------------------------------------------------------------------------------
URL        : POST /api/Waitlist/Join
USE        : Store a waitlist row. Does not reserve a slot and does not message anyone.
HOST       : New-API
TOKEN      : no
SAMPLE PAYLOAD:
{
  "doctorId": 1010,
  "patientId": 3065,
  "requestedDate": "2026-12-01",
  "consultMode": "In-clinic",
  "contactName": "Week3 Wait",
  "contactMobile": "7768046064"

OUTPUT     : { success, message: "Joined the waitlist. The slot is not reserved and no offer is sent." }

--------------------------------------------------------------------------------

             Offer is created when clinic cancels and frees a slot (APT-06). No auto-book / no fake paid.
             Require contactMobile and/or patientId. doctorId optional filter.
HOST       : New-API
TOKEN      : no (or patient JWT — same query)
SAMPLE     : GET /api/Waitlist/Offers?contactMobile=7768046064&doctorId=1010
OUTPUT     : { success, hasOffer, data: [ waitlist rows with status JOINED|OFFERED ] }

--------------------------------------------------------------------------------
URL        : GET /api/Waitlist?doctorId=
