PAT-18.02  Checkout (wire Phase 8–15 API)
================================================================================
Patient app checkout must use New-API fee + booking hold + consult order APIs.
Do NOT invent local paid/signed state. Do NOT POST PaymentStatus=PAID from the client
(Account / webhook / reception collection is SoT — REC-13 / Phase 6).

Flow
  1) Browse fee     GET  /api/Fees/Public/{doctorId}          TOKEN = no
  2) Hold booking   POST /api/Public/Doctors/{id}/Bookings    TOKEN = no (OTP session)
                    → paymentStatus=PENDING, consultFee, payAtClinicAllowed, bookingToken
  3) Poll hold      GET  /api/Public/Bookings/{bookingToken}  TOKEN = no
  4) Start checkout POST /api/Payments/ConsultOrders         TOKEN = yes (patient owns visit)
                    body: { patientAppId, payAtClinic?, amount?, idempotencyKey? }
                    → PAY_AT_CLINIC (UNPAID until reception) or AWAITING_GATEWAY (Razorpay)
  5) Status         GET  /api/Payments/Appointments/{patientAppId}  TOKEN = yes

UI mapping
  loading / offline / error / offline → network + HTTP codes
  show consultFee + currency from Fees/Public or booking response
  pay at clinic CTA only when payAtClinicEnabled / payAtClinicAllowed
  paid badge only from API paymentStatus (never local fake PAID)

PAT-30.02  Fallback & join failure handling (wire Phase 8–15 API)   TOKEN = yes
================================================================================
When live video join fails, patient app posts a standardised code and drives UI from
the API response (retry / rejoin / support). Do not invent local paid or "in call" state.

REQUEST
POST http://127.0.0.1:5038/api/Tele/Sessions/{sessionId}/JoinFailure
Authorization: Bearer <patient or doctor token>
Content-Type: application/json

{ "code": "DEVICE_DENIED" }

Canonical codes (aliases accepted; unknown → JOIN_FAILED):
  DEVICE_DENIED, NETWORK_ERROR, TOKEN_FAILED, VENDOR_ERROR,
  BROWSER_UNSUPPORTED, JOIN_FAILED

RESPONSE 200
{
  "success": false,
  "code": "DEVICE_DENIED",
  "message": "Camera or microphone was denied. Allow access and retry.",
  "retry": true,
  "rejoin": false,
  "supportPath": "/support",
  "allowedCodes": [
    "DEVICE_DENIED", "NETWORK_ERROR", "TOKEN_FAILED",
    "VENDOR_ERROR", "BROWSER_UNSUPPORTED", "JOIN_FAILED"
  ]
}

UI mapping
  retry=true           → Retry CTA (Token again)
  rejoin=true          → Rejoin CTA (only when session still Active)
  BROWSER_UNSUPPORTED  → retry=false (switch browser/app)
  supportPath          → open help/support (patient: /support; doctor: /doctor/support)
  offline/HTTP error   → offline/error screens; then retry JoinFailure when back

Events are stored on TeleSessionEvent (code = canonical). No PaymentStatus change.
